# Tasks: Test Automation Foundation and Lab Workflow Checks (Phase 1)

- **Functional Spec:** `functional-spec.md`
- **Technical Considerations:** `technical-considerations.md`

Each slice leaves the project buildable and runnable with `./mvnw` from the repository root, with one more piece of the functional spec working end-to-end, and the lab's own tests (run from `mock-lab-app/`) untouched.

**Verification conventions (used by every Verify task):**
- The framework needs a running lab but never starts one. Verify tasks start their own on a **spare port** so they never disturb a lab the engineer may be running on 8080: build the lab jar if missing (`cd mock-lab-app && ./mvnw -q -B clean package -DskipTests`), then `java -jar mock-lab-app/target/mock-lab-app.jar --server.port=18080 &`, wait with `curl -sf --retry 30 --retry-delay 1 --retry-connrefused http://localhost:18080/health`, and point the framework at it with `-DbaseUrl=http://localhost:18080`. Stop every process started and delete temp files at the end; never touch anything listening on 8080.
- Run Maven from the repo root through the **root wrapper** (`./mvnw`; `mvn` is not on the PATH). Never use `-q` when the "Tests run" summary is being checked, and never run `install`. Local JDK is 26 while the code targets Java 17 (`maven.compiler.release=17`); Maven's own JVM prints harmless `WARNING:` lines — ignore them.
- The framework does not use Mockito (it cannot mock classes on JDK 26); self-tests that need a fake lab use a tiny JDK `com.sun.net.httpserver` stub.
- Every task that adds tests proves them with RED validation (break the covered behavior, watch the test fail, restore exactly, watch it pass). Every Verify quotes real command output.
- The final slice maps all 37 functional criteria to evidence; criteria about commands (§2.1) and the pre-flight abort (§2.3) are proven by quoted command output rather than by unit tests.
